## Ledger rules

- These 44 rows are parent rollups, not proof that every child behavior is complete. Once the ADR-018 atomic matrix exists, the parent status is derived from its least-complete applicable child atom.
- The atomic guard, `startup`/`handoff` and user-triggered fresh-task drill now pass, but every parent remains `pending` until its active product task supplies current evidence; a manual status edit cannot bypass atom derivation.
- A row cannot leave `pending` until its active task writes a failing behavioral test and execution-control records the red command/exit code.
- `verified-local` requires current source, automated tests and required browser/visual evidence; a skipped MySQL, remote E2E or visual review is not a pass.
- `verified-image` requires smoke evidence against the intended immutable Web/API digests; `verified-registry` additionally requires UHub inspect, SBOM/provenance, matching production values and the validated deployment package. Only rows whose final boundary needs those artifacts may use the higher status.
- Argo `Synced/Healthy`, Kubernetes context and cluster-entry smoke are optional user deployment records, not states or completion gates in this Web ledger.
- Evidence paths must name sanitized artifacts. Credentials, raw personal content and private vault bodies never enter this file.
- Any plan/spec change updates this ledger before implementation resumes.
