# LifeOps Web 最终重设计规格

- 状态：`approved-design / amended-through-ADR-030 / uncommitted-local-checkpoint`
- 日期：2026-08-09；生活专区增量于 2026-08-10 批准；受控 UI 重设计于 2026-08-14 最终批准；参考锁定圆环、主题化登录层与完整入窗比例于 2026-08-23 批准；九个持续 transform 的原生 Web Animations 窄所有权例外于 2026-08-27 批准
- 基线：S012《公开轨道与夜景恢复》
- 决策：ADR-016、ADR-017、ADR-019、ADR-020、ADR-021、ADR-022、ADR-028、ADR-029、ADR-030
- 目标：完成 Web、API 与 MySQL 应用层，构建并推送 UHub 双镜像，交付用户可独立部署的 Helm/GitOps 包

## 1. 规格效力与边界

本规格汇总用户逐界面确认的最后一轮 LifeOps Web 重设计。实现、测试与部署必须逐条追踪本规格，不能把规划阶段确认的内容在行动阶段静默省略。

### 1.1 决策优先级

1. 用户在本轮逐项明确确认的要求。
2. 本规格、生活专区增量规格、执行完整性规格、镜像交付边界规格与 ADR-016、ADR-017、ADR-019、ADR-020、ADR-021、ADR-022、ADR-028、ADR-029、ADR-030；公开首页的参考锁定圆环、对象入轨、中心文案、登录比例、完整入窗和主题化登录表面以 ADR-029 为视觉专门决定，九个持续 transform 的调度所有权以 ADR-030 为最新窄专门决定。
3. `2026-08-10-lifeops-life-domain-design.md` 对生活专区的详细产品、数据和验收定义。
4. S012 中未被本轮调整的公开轨道与夜景基线。
5. 仍有效且不冲突的历史 ADR、部署合同与源码行为。

本规格取代旧规格中以下内容：三条规整 SVG 轨道、公开技术图标作为一级对象、私人星球/宇宙、私人区仅“今天/计划/记录/回顾/知识/发布”的薄功能壳、左侧功能栏加右侧卡片墙、直角纸片式后台和同尺寸圆角卡片墙。

### 1.2 受保护基线

- 公开首页常用且无有效用户 override 时的默认视觉为接近纯黑的 `#020306` 星空；星点疏密、大小与层次不规则。用户仍可显式切换清晰日景，私人区始终保持 daylight。
- 公开入口使用参考锁定的四条同心圆环：`1132×750` 归一化舞台、圆心 `(792,371)`、scale `.85`、base diameter `353/501/649/797`、同一条未补偿 `1px` masked gradient 和透明渐变断点。四轨承载五对象，允许两个对象共享一轨但最终角度必须分离，不恢复三轨或新增第五轨。默认态、登录态和全部断点的最外轨必须完整位于窗口安全边距内，禁止受控裁切或隐藏越界。
- 公开入口只通过点击轨道对象进入详情；滚轮只执行浏览器原生滚动，不承担进入、退出或状态切换。
- 公开详情始终有固定返回路径；浏览器返回与 `Esc` 行为一致。
- 私人区保持明亮、直观、适合长期使用，不继承星球、银河或深色宇宙主题。
- 若产品或文档提及用户当前集群，仍按 Phase-1 `2 LB + 1 control-plane + 2 worker` 描述，不能冒充控制面高可用；该集群不属于 Web 项目实施范围。
- LifeOps V1 发布主线为 GitHub Actions + UHub + Argo CD；Jenkins 只保留为后续等价流水线学习轨，Harbor 只保留为可选镜像方案。

## 3. 公开首页

### 3.1 构图

- 桌面首屏左侧约 36% 为 LifeOps 字标、简短主张与状态文字，右侧约 64% 为轨道主场景。
- 顶栏只保留字标、昼夜切换与登录，不重复放置五个内容导航。
- 场景中心移除网站基座、`PRIVATE SYSTEM` 黑球和旧“时间脉冲”，改为不可点击的安静日光孔径；孔径只承担公开与私人世界的连续入口，不承载第二套仪表盘信息。
- 轨道、对象和标签属于同一场景坐标系；缩放、位移与响应式变化必须同步。
- 四轨圆环在桌面默认态占据右侧主视觉，`1440×900` 以 `677.45px` 外径为基准；最外轨、对象、标签和交互锚点四周均保留至少 `16px` 视口安全边距，不能靠 `overflow:hidden/clip` 掩盖任何越界。
- 左侧真实标题固定为“把日子，慢慢看清。”，以中文逐字、一次性的克制暖紫/星光光标显现；辅助文案与入口随后轻微 stagger。不得循环清空重打，也不得因登录打开、关闭或重开而重播。

### 3.2 五个语义对象

| 对象 | 图形 | 内容 |
|---|---|---|
| 此刻 | 日晷 | 当前状态、今日/本周节奏 |
| 正在做 | 导航旗 | 活跃目标、项目与 LifeOps 工程进度 |
| 最近在学 | 展开的书 | 学习主题和最近笔记 |
| 生活切片 | 取景框 | 照片、短记录和生活片段 |
| 时间档案 | 年轮/档案环 | 年月索引、历史快照和公开归档 |

对象标签必须可见，不能只在悬停时出现。桌面和平板显示完整短标签；手机显示不改变语义的短名称，并通过碰撞检测调整标签位置而不是隐藏标签。图形、名称和目标页面一一对应，技术栈图标不再承担一级导航。

五个对象统一重绘为同一套 authored SVG 线性语言：一致的 stroke、圆角、光感与视觉尺寸，减少大色块、厚圆章和装饰容器。对象根中心必须精确在所属 path 上；小锚点、短连接或切线关系只用于表达“挂”在轨道上，图标本身始终 upright、可辨且标签全断点常驻不碰撞。

### 3.3 轨道与运动

- 轨道固定为参考锁定的四条同心圆环。统一 `1132×750` 场景坐标，圆心 `(792,371)`；base diameter 为 `353/501/649/797`，统一 scale `.85` 后精确屏幕直径为 `300.05/425.85/551.65/677.45px`。不得改用 `.866` 拟合、偏心椭圆、等间距重算或第五条轨道。
- 四轨共享同一条未补偿 `1px` masked gradient：`rgba(217,161,255,0) 0% → rgba(217,161,255,1) 43% → rgba(217,161,255,0) 100%`。透明段就是轨道断点，不增加连续底线、补偿线宽、drop-shadow 或每圈独立 opacity。
- 四轨持续自转，方向/周期依次为 `CCW 30s`、`CW 40s`、`CW 50s`、`CCW 60s`。五对象映射到四轨并保持最终角度 `314/236/161/96/88deg`；共享轨道的两个对象保持分离角度。
- 原生 Web Animations API 只拥有四个持续圆环 rotation transform 与五个对应的 upright counter transform。GSAP 不写这九个持续 transform；CSS animation/transition、Motion 或第三个引擎也不得写入这些节点的 transform。该窄所有权例外只改变调度层，不改变方向、周期、相位、暂停/恢复、登录三分之一速度、hidden/offscreen/reduced-motion 或 live playhead 合同。
- 每个对象的局部进度 `u=clamp((time-delay)/0.72s,0,1)`，缓动 `E=cubic-bezier(.22,1,.36,1)(u)`；半径为 `finalRadius×(.3+.7E)`，相对所属旋转轨道的角度为 `finalAngle-180°(1-E)`，局部 scale 为 `.3+.7E`、rotation 为 `-180°(1-E)`、blur 为 `10px(1-E)`，opacity 在 18% 时到 1。延迟固定为 `.60/.80/1.00/1.20/1.40s`；独立 counter 层抵消定位角度扫掠，避免图标自身旋转被叠加，结束帧必须无跳变衔接持续自转。
- 整组使用独立的 1.2 秒 `.85→1` scale-in；该组入场、四轨持续旋转、对象入轨和图标自身动画不得混成一个 transform owner。中心计数 `00→05`，下方文案固定为“此刻正在发生”。fallback 与 enhanced DOM 使用同一语义、轨道定义、初始/最终几何和 reduced-motion 稳定帧。
- 登录时圆环持续运行但速度降至三分之一；关闭从当前相位恢复，不重播整组入场、对象入轨或计数。
- 夜景增强轨道线可见度，但不改回蓝灰大渐变或规则点阵。
- 页面不可见时暂停高频计算；减少动态效果时对象静止在轨道上，内容仍可点击。
- 移动端等比缩放并重排轨道与对象；最外轨在窗口四边保持安全边距，不出现裁切、横向溢出、标签遮挡或触控目标过小。

## 4. 公开详情与登录边界

### 4.1 公开详情

- 详情在首页上方形成独立 `100dvh` 内容层，而不是把用户抛到无关模板。
- 顶部固定约 64px 控制带始终显示返回、当前栏目与必要操作；移动端同时提供易触达的底部返回。
- 返回后恢复首页滚动位置、轨道相位、昼夜状态和焦点来源。
- 详情使用 12 列内容画布，首屏同时出现主内容与至少两个有意义的相关上下文，不让单一内容占半屏、其余空间空置。
- 此刻采用当前状态与周节奏；正在做采用项目进度与技术底座；最近在学采用主题与笔记；生活切片采用视觉时间流；时间档案采用年月索引与快照。
- 公开页面只读取已发布副本，绝不自动展示私人原文。

### 4.2 登录层

- 桌面端登录面板从右侧进入，宽度约 460px，完整表单在一个视口内，不需要滚动寻找退出或提交。
- 首页右侧圆环作为一个场景整体左移、缩小和降亮。`1440×900` 登录态目标为约 `520px` 外径、`460px` 面板、两者可见边界间约 `32px`、垂直中心偏差不超过 `16px`；`900–1179px` 使用约 `360–430px` 外径和 `400–440px` 面板。圆环速度减至原来的约三分之一但继续运动，最外轨始终完整入窗。
- 关闭登录时从当前轨道相位反向恢复，不重新开始动画。
- 星空 night 下登录面板使用深靛黑半透明身份边界、冷紫细边、遮挡型 blur、有偏移的黑紫软阴影、暖白正文和浅紫高对比主按钮，不得呈现白色面板；显式 day 保留协调的浅色表面。成功登录后圆环继续向左退出，登录面板扩展并转换成私人 daylight 总览；真实鉴权成功才触发该过程。
- 常规登录过渡为约 580～720ms，批准基准为约 680ms；减少动态模式取消孔径扩张和大位移，以不超过约 80ms 的即时颜色/透明度连续性进入已预绘制私人画布。
- 支持账户、密码、显示密码、错误、进度、密码管理器、键盘操作、焦点约束、`Esc`、遮罩与明确关闭。
- `<=899px` 使用稳定星盘背景上的全屏登录任务层，表单最大宽度 `420px`，night 保持深色；圆环只作为低对比背景且最外轨完整入窗，返回操作固定可见，打开任务层不得重启星盘。
- 登录打开、关闭、反向关闭或重开不得重启左侧标题、五对象 playhead 或用户主题；LoginWindow 的字段、验证、请求、成功鉴权、`Esc`、focus trap、返回、460px 桌面与移动全屏合同保持不变。

## 5. 私人全局外壳与总览

### 5.1 全局外壳

- 私人区使用明亮、温暖、清晰的“日光指挥台”，不再出现星球或轨道。
- 顶栏稳定存在；路由切换只重组内容空间，不整页卸载或白闪。
- 画布为全宽 12 列非对称结构，不采用左侧栏加通用卡片墙。
- 颜色语义：蓝色代表计划/时间，暖黄代表目标/专注，绿色代表习惯/节奏，紫色代表回顾/知识，橙色代表警告。颜色控制饱和度并保持协调。

### 5.2 总览 `/app/overview`

- 顶部状态带：日期、问候、周进度、快速创建和平台健康摘要。
- 左侧约 7 列：今天时间线、当前时间、日历块、任务与空档。
- 右侧约 5 列：当前重点目标、活跃项目和下一步行动。
- 下方包含习惯七日节奏、本周趋势、最近记录、上次回顾结论和重新浮现的知识。
- `1440×900` 首屏必须看到所有主要板块；大时间线不能制造无效空白。
- 动态日光带随当天时间轻微变化，只增强层次，不影响阅读。
- 单个动态组件失败时原位降级并允许重试，不能拖垮整个总览。
- 增加紧凑“今日生活”摘要，只显示下一餐、补剂/药品、训练、营养进度、紧急采购和预计支出；完整生活操作进入 `/app/life`，不得用生活模块吞掉跨域总览。

## 6. 私人功能页面

### 6.1 目标与项目 `/app/goals`

- 顶部展示当前三个优先目标与季度进度。
- 左侧约 8 列为横向结果地图：目标带、项目条、里程碑与当前日期。
- 右侧约 4 列为所选对象检查器：进度、风险、下一任务、近期记录与编辑。
- 下方明确列出停滞、逾期和缺少下一步行动的项目。
- 支持目标、项目、里程碑完整增删改查，暂停、完成、归档与同一身份恢复，日期、计算/手动进度，以及与任务、记录和回顾关联；项目风险备注是独立持久化事实，不编码进描述，恢复使用 owner/version 保护并留下关联原归档事件的补偿 reversal 审计。
- 移动端重排为目标 → 项目 → 里程碑 → 下一行动。

### 6.2 日程 `/app/schedule`

- 默认周视图；左侧约 8 列为周历，右侧约 4 列为今日、临期、未排期和逾期任务池。
- 支持日/周/月、项目和状态筛选。
- 任务支持标题、说明、项目、起止时间、截止时间、预计时长、优先级、状态、标签、清单和重复规则。
- 支持拖动排期、改期和调整时长，同时提供键盘/表单替代方案、冲突与超载提示以及撤销。
- 手机优先显示单日安排；空状态提供创建任务、从目标拆解和创建重复项。

### 6.3 习惯 `/app/habits`

- 顶部展示今日习惯；左侧约 8 列为 28 天节奏矩阵，右侧约 4 列为所选习惯详情与统计。
- 规则支持每日、指定星期、每周次数和自定义周期；计量支持完成、次数、时长和数量。
- 支持目标值、时间、起止日期、目标/项目关联、暂停、归档与编辑；目标/项目关联必须通过只增迁移持久化，并拒绝跨用户或错误层级引用。
- 完成、部分完成、主动跳过和遗漏必须清楚区分并成为回顾证据。
- 不使用火焰、金币、徽章等刺激性游戏化。

### 6.4 记录 `/app/records`

- 顶部提供日期、标签、来源和全文筛选。
- 左侧约 8 列为按日期分组的时间流；右侧约 4 列为快速记录或完整编辑器。
- 支持标题、Markdown、时间、标签、任务/项目/目标/习惯关联、图片与封面、自动保存、编辑、置顶、归档和删除。
- 封面以持久化的可空 `coverMediaId` 表达：创建默认 `null`，PATCH 省略时保留、显式 `null` 时清除、非空时选择；非空值必须属于同一用户且包含在该记录的 `mediaIds` 中。移除活动封面必须在同一请求中清除或替换，否则整个版本化写入失败；数组首项、UI-only 状态和封面身份均不得绕过私人媒体授权。
- 页面 URL 的单个 `source=` 只接受一次解码的 `<goal|project|task|habit>:<non-empty-id>`，按第一个冒号拆分并把其余冒号保留在 ID 中；空值表示不筛选。合法值只映射到既有 `linkType + linkId`，malformed 或重复值显示局部筛选错误且不发送畸形请求，不做跨表推断或 fallback。
- 已完成任务可以生成记录；记录可以提炼为知识、回顾证据或公开草稿。
- 默认严格私有，发布必须进入独立发布流程。

### 6.5 回顾 `/app/reviews`

- 采用 3/6/3 结构：左侧证据目录、中间叙事回顾、右侧洞察与行动。
- 支持周回顾、月回顾与自定义周期。
- 聚合目标、项目、任务、习惯、记录与上次承诺；统计是确定性计算，不伪造洞察。
- 用户填写成果、问题、原因、洞察和下一步变化。
- 支持草稿自动保存、编辑、归档、删除；行动可转换为任务、目标更新、知识或公开草稿。

### 6.6 知识 `/app/knowledge`

- 桌面三栏：左侧约 2.5 列为集合/主题/标签，中间约 3.5 列为笔记列表，右侧约 6 列为阅读和编辑区。
- 支持标题、正文、标签和来源搜索；可直接创建，也可从记录、回顾、目标和项目提炼。
- 支持 Markdown、集合、关联知识、置顶、收藏、归档、删除、公开草稿和复习日期。
- 首页和知识页提供基于规则的“重新浮现”，不使用无意义关系图。

### 6.7 生活 `/app/life`

- 生活专区是独立业务域，详细权威为 `2026-08-10-lifeops-life-domain-design.md`，需求范围为 LIFE-01 至 LIFE-24。
- 二级导航精确为 `今日｜计划｜食谱｜库存｜健身｜采购｜分析｜数据`；角落日历作为常驻时间入口，不再占用一个二级导航标签。食材、补剂、药品和家庭物品通过上述任务域及数据管理进入，不恢复含糊的“资料库”总入口。
- 角落日历串联模板、日期计划和实际完成；未来/未完成计划使用当前基础数据自动重算，已完成记录保存当时营养、价格、配方和用量快照。
- 食材、补剂、药品和家庭物品共享分类、标签、单位、价格、库存、批次、位置、采购、回收站和审计基础能力，但按用户任务分页面呈现。
- 食谱连接原料、步骤、份数、营养、成本、版本、做菜记录和剩余成品；食材与食谱可双向查询。
- 周模板应用后形成独立日期计划；模板修改不静默覆盖日期，日期复制不复制实际完成、库存事务或历史支出。
- 统一采购闭合低库存/计划缺口、购买、入库、价格和预算；现金支出与消耗成本分别统计，不重复相加。
- 药品只做用户录入、库存、有效期、排程和历史记录，不给出诊断、剂量、停药或未经验证的相互作用建议。
- 界面继续使用日光指挥台、连续画布、软体积和不同尺度任务模块，不形成卡片墙或第二套视觉世界。

### 6.8 发布 `/app/publish`

- 左侧约 3 列为私人来源库，中间约 5 列为公开草稿编辑器，右侧约 4 列为昼夜、桌面和移动预览。
- 状态：草稿、计划发布、已发布、已撤回。
- 公开类别固定对应五个轨道对象。
- 支持从私人内容复制或独立创建；字段包含标题、摘要、Markdown、封面、标签、类别、slug、发布时间、精选状态、SEO 和分享预览。
- 支持预览、立即/定时发布、更新、撤回、版本历史和差异查看。
- 发布前显示隐私审查；撤回后公开接口不可访问；提供 RSS 和稳定链接。

### 6.9 平台运行中心 `/app/platform`

子导航：`总览｜Kubernetes｜监控｜告警｜日志｜发布｜技术档案`。

- 总览顶部显示 Web、API、MySQL、Kubernetes、Prometheus、Alertmanager、Elasticsearch 和 Argo CD 的真实连接状态与刷新时间。
- 主区包含服务拓扑、集群工作负载、当前告警、最新部署、资源/可用性趋势、错误日志摘要和 GitOps 状态。
- Kubernetes 只读展示节点、Deployment、StatefulSet、DaemonSet、Pod、Service 与 HTTPRoute；不读取 Secret，不允许 exec、创建、修改或删除。
- 监控只提供预设 SLI 查询：可用率、P95 延迟、请求量、错误率、CPU、内存、存储、就绪与重启；深入查看跳转 Grafana。
- 告警展示当前与近期恢复状态，操作跳转 Alertmanager；LifeOps 首版不直接静默告警。
- 日志返回脱敏、限量的 Elasticsearch 摘要并跳转 Kibana。
- 发布展示 Web/API 镜像标签与 digest、GitHub Actions、Argo CD 同步/健康、部署时间和历史版本；首版只读，不提供绕过 GitOps 的部署按钮。
- 技术档案覆盖 React、TypeScript、MySQL、Docker、Kubernetes、Helm、GitHub Actions、Argo CD、Prometheus、Grafana、Alertmanager、Elasticsearch、Kibana、Elastic Agent/Filebeat；Jenkins 标为后续学习轨，UHub 标为当前镜像主线，Harbor 标为可选。
- 未配置服务必须显示“未连接/未验证”，不得生成假数据。

### 6.10 设置 `/app/settings`

- 分类：账户与会话、外观与动效、时间与区域、默认行为、Obsidian、平台连接、公开站点、数据与安全。
- 平台凭据只来自服务端环境或 Kubernetes Secret，设置页只显示状态和非敏感配置，不回显 Secret。
- 支持数据导出、恢复预检、危险操作确认和审计记录。
- 设置使用连续空间中的分类导航与内容区域，不堆叠纸片卡片。

### 6.11 全局搜索与快速创建

- `Ctrl/Cmd+K` 在所有私人页面打开搜索；结果按目标、项目、任务、记录、回顾、知识、生活对象和公开内容分组。
- 支持键盘选择、最近访问、筛选和直接跳转；平台日志不混入个人内容搜索。
- 快速创建支持任务、记录、知识、目标/项目、习惯、回顾草稿、生活基础数据、日期计划、临时采购和实际饮食记录；从当前页面继承项目、日期或对象上下文。
- 创建完成允许留在当前页、打开新对象、撤销或继续创建。

## 7. Obsidian 集成

- V1 使用浏览器 File System Access 能力连接用户明确选择的本地目录，不要求额外 Obsidian 插件。
- 建议目录：`LifeOps/Knowledge`、`LifeOps/Reviews` 与用户选择的 `LifeOps/Life` 子目录。
- Markdown frontmatter 至少包含 `lifeops_id`、类型、标签、来源、更新时间和同步版本。
- 初次连接只扫描和预览，不立即批量写入。
- 同步由用户手动触发，采用双向预览；冲突展示 Web 与 Obsidian 两个版本，由用户保留、合并或复制。
- 删除不自动同步；批量写入前创建备份；支持 Obsidian URI 打开文件。
- 不支持 File System Access 的浏览器降级为 Markdown/ZIP 导入导出与 Obsidian URI。
- 生活同步只覆盖食谱、做菜心得、健身摘要、生活回顾和用户选择的采购/预算摘要；实时库存、库存事务、幂等状态、预算计算和日历冲突只保存在 MySQL。
- 生产环境不得硬编码或假设可访问个人电脑 `D:` 路径；Obsidian 内容始终是受控知识副本，不替代结构化业务事实源。
- V1 只同步知识与回顾，不同步账户、任务、平台连接或运行日志。

## 8. 视觉空间与动效系统

### 8.1 连续画布与软体积

- 不采用直角纸片式后台，也不采用同尺寸圆角卡片墙。
- 页面以连续画布、色域、留白、分隔轨道和内容密度划分区域。
- 核心工作区使用宽缓的软体积，可嵌入、交叠或从边缘延伸；浮动操作和临时面板才抬升。
- 阴影只表达遮挡关系；图表、列表、时间线和文字尽量融入所属区域，不额外套娃。
- 表格使用连续数据带/行列结构，不拆成一张张纸片。
- 空间分为环境层、工作层和操作层；每个首屏必须有明确主角、次级信息和呼吸区。
- 玻璃效果只允许少量出现在悬浮控制中，不能铺满页面。

### 8.2 连续转场

- 全局外壳稳定，一级页面只重组内容区。
- 列表进入详情使用标题、色块或位置的共享元素过渡；返回执行反向过程并恢复滚动、筛选、选中与展开状态。
- 编辑器、筛选和检查器优先采用局部展开层或侧滑层，不为小操作频繁跳转整页。
- 数据刷新局部交叉淡化，保留布局骨架，不整页白屏。
- 快速连续操作从当前动画进度衔接，不重播、不排队。
- 节奏 token：反馈 120ms、局部状态 180ms、私人任务区 240ms、任务层进入/退出 320/220ms、登录打开/关闭 480/360ms、孔径 680ms、昼夜变化 900ms。退出快于进入，不使用反射性 bounce、elastic 或弹簧回弹。
- 动画主要使用 `transform` 与 `opacity`；避免大面积模糊、弹跳和装饰性旋转。
- 除四个持续圆环 rotation 与五个 upright counter transform 由原生 Web Animations API 窄独占外，公开首页标题/整组入场/对象入轨、公开详情连续性、登录、场景和孔径继续由 `gsap@3.15.0`、`@gsap/react@2.1.2`、GSAP Core 与 MotionPathPlugin 独占；私人产品继续由 Motion 独占。任何节点及其 transform 属性不得被两个引擎或 CSS animation/transition 同时写入。禁止 ScrollTrigger、ScrollSmoother、滚轮导航、全站视差和通用滚动揭示。
- 左侧标题入场同样由公共 GSAP owner 独占，只动画 `transform`、`opacity` 与极小有界 blur。完整标题及其 accessible name 从首帧可读；逐字视觉 span 对读屏隐藏。无 JS/增强失败时直接显示完整标题；reduced-motion 直接稳定显示完整标题且不运行循环光标。
- 星盘提供位于页头控制组的 44px 暂停/继续图标按钮，不保留右下悬浮胶囊。对象获得键盘焦点或指针停留时暂停其所属共享圆环；页面隐藏、场景离开视口或用户暂停时停止环境循环。减少动态模式停止环境漂移和对象入轨，直接显示完整稳定帧，并以不超过约 80ms 的必要颜色/透明度变化保留状态连续性。
- 四条 masked-gradient 圆环各自持续旋转；定位层、路径 counter、upright counter 和图标 material 分层拥有 transform，其中四个 ring rotation 与五个 upright counter 由原生 Web Animations 独占，其余层由 GSAP 独占。任何单节点不得出现 CSS/GSAP/Web Animations/Motion 的 transform 所有权竞争；登录整组位移/缩放不能重置各圈或对象 playhead。

## 9. 响应式、状态与可访问性

- 正式验收视口固定为 `1440×900`、`1024×768`、`768×1024` 和 `390×844`，另以 320 CSS px 做回流压力测试。宽屏同时展示主工作区和上下文；紧凑桌面把私人头部分成身份/工具行与完整导航行；平板按主任务重排；手机一次呈现一个任务层。页面本身不得横向溢出，只有带可见提示和键盘操作的内部导航带/时间轴可以横向滚动。
- `1440×900` 首屏必须包含当前页面的核心功能；返回、保存、关闭和主操作始终可见。390 端不得以汉堡菜单隐藏十项一级信息架构，当前导航项必须自动进入可视区域。
- 每个页面实现：初次加载、正常、空、局部加载、保存中/已保存、权限不足、网络异常、冲突、删除/撤销和服务未连接状态。
- 状态合同同时覆盖延迟、403、409 版本冲突、500、离线草稿、部分数据、重复提交、归档/恢复，以及平台 connected/degraded/disabled/unknown；局部失败不得替换整页，缺失不得伪装成零。
- 空状态必须给出上下文下一步；错误在对应模块或字段解释并允许重试。
- 未保存内容离开时提醒；自动保存失败保留本地草稿；写操作具有幂等或版本保护。
- 所有导航、菜单、对话框、编辑器和拖动操作都有键盘方案；`Ctrl/Cmd+K` 打开搜索，`Ctrl/Cmd+/` 打开快速记录，`Esc` 只关闭最上层；日历/矩阵采用正确的方向键网格模型，拖拽同时提供 Enter 拾取、方向键移动、Enter 确认、Esc 取消或等价表单。
- 前进转场后焦点进入新页面标题或主工作区；浏览器返回恢复来源控件、滚动、筛选、选中和展开状态。真正模态层使背景 inert 并约束焦点，普通检查器不制造焦点陷阱；固定头尾不得遮住焦点。
- 最低符合 WCAG 2.2 AA，正文对比度不低于 4.5:1、关键非文字边界不低于 3:1，并采用更严格的 44×44 主要触控目标、200% 文本缩放、320 CSS px 回流和不依赖颜色的状态表达。

## 10. 系统架构与数据

### 10.1 技术边界

保留当前 `React + TypeScript → Fastify + TypeScript → MySQL 8.4`，按领域拆分前端路由、API 路由、服务和数据访问，不进行与目标无关的技术栈替换。

- API 统一使用 `/api/v1`、JSON Schema 校验、request id 和一致错误格式。
- 生产前端只读取真实 API；本地演示数据必须显式标识，不能混入生产。
- 数据库变更通过版本化迁移执行；跨对象写入使用事务。
- 自动保存、重试和快速创建使用版本号或幂等键防止覆盖与重复。

### 10.2 核心模型

模型覆盖用户/会话/设置、目标、项目、里程碑、任务/清单/重复规则、日程块、习惯/规则/打卡、记录/附件、回顾/证据/行动、知识/集合/关系、公开草稿/版本、生活物品与分类/标签/单位/价格、库存批次与流水、食谱与版本、计划模板/日期计划/完成快照、健身、采购/退货/预算、回收站、导入导出、媒体、同步、审计事件。

- 每条私人数据按 `user_id` 隔离。
- 旧 `plans` 数据迁移或映射为新任务，不清空历史；旧公开快照继续可追溯。
- 删除默认可恢复；目标/项目/里程碑恢复保留同一 ID、执行版本检查，并以新的 reversal 审计事件关联当前归档周期的原事件；发布、撤回、Obsidian 同步、导入和批量写入同样保留审计或版本。
- 公开内容从私人来源复制到公开草稿，再生成不可变发布版本；公开 API 无法读取私人原文。
- 全局内容搜索首版由 MySQL 内部索引承担，不强制复用用于日志的 Elasticsearch。
- 生活未来预测从当前有效主数据派生；完成事件保存历史快照。完成/撤销、购买/入库/支出和退货/退款分别使用单一数据库事务与幂等键，禁止重复扣减和半完成状态。

### 10.3 媒体存储

- 媒体使用可替换存储适配器。当前集群若验证了 NFS StorageClass，则可使用 PVC，但必须标记单点边界；若存在兼容 S3 的对象存储则可切换对象存储。
- 上传验证类型、大小与内容，使用随机键并生成必要缩略图；数据库只保存元数据。
- 私人附件经鉴权读取；公开媒体使用单独公开路径。

## 11. 安全与外部适配器

- 密码继续遵循现有 scrypt 合同并使用每用户随机盐；会话使用服务端摘要和 `HttpOnly + Secure + SameSite=Lax` Cookie。
- 写接口执行同源/CSRF 防护；登录、公开读取和敏感操作限流。
- Markdown 与链接在渲染前净化；导入和恢复先预检再写入。
- Kubernetes、Prometheus、Alertmanager、Elasticsearch、Argo CD 等由 API 服务端只读适配器访问。
- 外部地址来自配置允许列表，禁止任意 URL，限制查询、超时和响应大小；凭据不得进入浏览器、日志、数据库导出或项目文件。
- Kubernetes ServiceAccount 使用最小 RBAC；绝不授予 Secret 读取、Pod exec 或工作负载写权限。
- 聚合结果短时缓存；浏览器只在页面可见时轮询；部分外部服务失败不影响其他模块。

## 12. 测试与质量门禁

- 单元测试覆盖统计、重复规则、状态转换、发布、权限和数据转换。
- API 集成测试覆盖登录、CRUD、事务、并发版本、用户隔离、公开/私有边界和失败恢复。
- Playwright 覆盖公开点击导航、详情返回、昼夜、轨道几何、登录连续转场、所有私人关键流程、生活日历/计划/做菜/库存/采购/预算/恢复、发布/撤回、Obsidian 降级、平台未连接、移动端和减少动态。
- 视觉回归覆盖常用桌面、平板与手机；人工复核层次、首屏利用率、纸片/卡片反模式和动效连续性。
- 验收必须运行 TypeScript、单元、API、真实 MySQL、E2E、生产构建、精确 digest 镜像 smoke 和 Helm lint/template；用户部署后的集群 smoke 由交付脚本支持，但不是 Web 完成门禁。
- 每条需求 ID 必须关联实现位置、测试和验收证据；没有证据不能标为完成。

## 13. 实施分解与阶段门禁

本项目使用一个主规格，但实施必须拆为可独立理解、可运行和可验证的纵向工作包：

1. **基础与兼容**：设计令牌、稳定应用外壳、领域数据库迁移、旧计划/路由兼容、统一 API 与测试夹具。
2. **公开入口与身份边界**：公开轨道、五类详情、发布副本读取、登录连续转场。
3. **私人核心生活闭环**：总览、目标/项目、日程/任务、习惯、记录、回顾，以及生活专区的今日、日历、资料库、计划、采购、分析和数据管理。
4. **知识与内容流转**：知识库、Obsidian、发布工作台、版本与公开站点。
5. **平台与全局工具**：平台运行中心、搜索、快速创建、设置、导入导出与审计。
6. **生产交付**：全量回归、双镜像、UHub、Helm/GitOps 部署包、用户操作手册与事实源回写。

每个工作包都必须同时完成数据、API、界面、状态、自动测试和视觉验收，再进入下一个工作包。允许后续工作包复用已完成基础，但不允许先在所有页面留下占位实现。

## 14. 镜像、GitOps 与用户部署交接

- GitHub Actions 依次执行检查、测试、生产构建、安全检查、Web/API 镜像构建与推送、digest 解析和 GitOps values 更新。
- 镜像推送 UHub，使用版本、Git SHA 与 digest，不以 `latest` 作为部署事实。
- Argo CD 是用户集群中的推荐同步和漂移检测方式；CI 不持有 kubeconfig，不直接修改工作负载，Web 项目也不执行 Argo 同步。
- Helm Chart 覆盖 Web/API Deployment 与 Service、HTTPRoute、ConfigMap、Secret 引用、健康检查、资源请求/限制、安全上下文、RBAC、迁移 Job、媒体存储、ServiceMonitor、PrometheusRule 和 Grafana dashboard。
- 迁移采用向前兼容策略；上线前备份和预检，应用回滚不盲目反向执行破坏性数据库迁移。
- 正式发布前验证 Git 仓库、UHub 凭据、Docker/Buildx、双仓库、生产 values 和发布清单；用户部署前另按交付清单验证 kubeconfig、StorageClass、业务入口、DNS/TLS 和平台连接。
- Web 项目真实验收覆盖本地/CI 的公开与私人访问、CRUD 持久化、媒体、发布边界、健康检查、平台状态诚实性、精确 digest 镜像和真实浏览器体验。Argo 状态、Pod 重建和集群入口 smoke 由用户部署后执行。
